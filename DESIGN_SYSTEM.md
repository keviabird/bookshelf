# Design system rules (Figma → SwiftUI)

Rules for turning Figma designs (via the Figma MCP server) into code for «Книжная полка».
Figma MCP output is usually React + Tailwind: treat it as a **visual reference only** and
rewrite it in SwiftUI following the rules below. Never add web code, CSS or third-party UI libraries.

## 1. Tokens

There is **no custom token layer yet**. The app relies on Apple's system design tokens:

| Kind | Source | How it's used |
|---|---|---|
| Accent color | `Bookshelf/Assets.xcassets/AccentColor.colorset` (empty → system blue) | `.tint`, `Color.accentColor`, prominent buttons |
| Semantic colors | SwiftUI | `.primary`, `.secondary`, `.red` for errors, `.bar` for banners |
| Typography | Dynamic Type text styles | `.headline`, `.subheadline`, `.caption` |
| Spacing / radius | Inline literals | `spacing: 2 / 12`, `.padding(12)`, `cornerRadius: 6` |

Build settings: `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME = AccentColor`,
`ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS = YES` (colors/images added to
the catalog get type-safe Swift symbols generated by Xcode).

**Mapping Figma values:**
- Figma color variables → a named Color Set in `Assets.xcassets` with **Any + Dark** appearances.
  Use it via the generated symbol or `Color("Name")`. Don't hardcode hex/RGB in views.
- If a Figma color matches a system color (label, secondary label, system background, red…),
  use the system semantic color instead of adding a new asset.
- Figma brand/primary color → set it on `AccentColor` rather than creating a parallel "primary".
- Figma text styles → nearest Dynamic Type style (`.largeTitle … .caption2`) + `.weight(...)`.
  Fixed `.system(size:)` only for tiny decorative text (e.g. `BookCoverView` placeholder),
  never for body copy — the app must support Dynamic Type.
- Figma spacing/radius → keep literal values in pt, they map 1:1. If the same value appears in
  3+ places, extract a constant (e.g. `enum Layout { static let rowSpacing: CGFloat = 12 }`)
  in `Bookshelf/Views/` instead of copying it.

## 2. Components

- Location: `Bookshelf/Views/`, one `struct …: View` per file, file named after the type.
- Two kinds of views:
  - **Screens** (`BookListView`, `AddBookView`) own a ViewModel via `@State`, injected in `init`.
    They never touch SwiftData or `@Query` (MVVM rule from CLAUDE.md).
  - **Presentational components** (`BookCoverView`) take plain values (`String`, `URL?`, enums),
    not ViewModels or `ModelContext`. New Figma components go here.
- Any non-trivial layout logic in a component is a `static func` so it can be unit-tested
  (see `BookCoverView.placeholderFontSize(for:)` + `BookshelfTests/BookCoverViewTests.swift`).
- Documentation = `#Preview` at the bottom of each file. Show the important states
  (empty, long text, error). Previews needing data build an in-memory `ModelContainer`.
- Prefer native containers over custom chrome: `NavigationStack`, `List`, `Form`/`Section`,
  `ContentUnavailableView` (empty/error states), `.toolbar`, `.sheet`.

```swift
// Presentational component pattern (Bookshelf/Views/BookCoverView.swift)
struct BookCoverView: View {
    let title: String
    let coverURL: URL?

    var body: some View { … }

    static func placeholderFontSize(for title: String) -> CGFloat { … }
}

#Preview {
    HStack { BookCoverView(title: "Я", coverURL: nil) }
}
```

## 3. Frameworks & build

- SwiftUI only (no UIKit), SwiftData for storage, iOS 17.0 deployment target, Xcode 26.
  APIs newer than iOS 17 (e.g. Liquid Glass `.glassEffect`) need `if #available`.
- Swift 5 mode with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`.
- Build system: Xcode project with file-system-synchronized groups — new files under
  `Bookshelf/` are picked up automatically; don't edit `project.pbxproj`.
- No SPM packages. Don't add design/UI dependencies without approval.

## 4. Assets

- All bundled assets live in `Bookshelf/Assets.xcassets` (currently only `AppIcon`, `AccentColor`).
- Figma images/illustrations → export as **PDF or SVG** (vector, "Preserve Vector Data") or PNG
  @2x/@3x, add as an Image Set, reference via generated symbol / `Image("name")`.
  Do not use the localhost asset URLs from Figma MCP output in code.
- App icon: single 1024×1024 with Any / Dark / Tinted variants (`AppIcon.appiconset`).
- Remote images (book covers) come from `Book.coverURL` and load with `AsyncImage`; always
  provide placeholder + failure states (see `BookCoverView`). No CDN or image cache layer.

## 5. Icons

- Use **SF Symbols** only: `Label("…", systemImage: "books.vertical")`, `Image(systemName:)`.
- Used today: `plus`, `books.vertical`, `exclamationmark.triangle`.
- Figma icon → find the matching SF Symbol (SF Symbols app). Only if none fits, export it as an
  SVG **Symbol Image** into the asset catalog, named in kebab/dot style like SF Symbols
  (`book.cover.placeholder`).
- Icon-only buttons still use `Label` so VoiceOver gets text; decorative images get
  `.accessibilityHidden(true)`.

## 6. Styling

- No CSS concept: styling is SwiftUI modifiers applied inline in the view.
- Global style: only `AccentColor` (and system light/dark appearance). No custom
  `ButtonStyle`/`ViewModifier` yet — create one in `Bookshelf/Views/` when a Figma style is
  reused in several places, instead of repeating modifier chains.
- Colors for states: errors `.red`, secondary text `.secondary`, status/highlight `.tint`.
- Every new screen must work in **light and dark** mode and with large Dynamic Type sizes.
- Responsive layout: app runs on iPhone and iPad (`TARGETED_DEVICE_FAMILY = 1,2`), portrait and
  landscape. Use flexible stacks/`List`/`Form`, `Spacer`, `frame(maxWidth:)`; avoid fixed screen
  widths. Fixed sizes are fine for small elements (cover thumbnail 48×72).
- UI strings are Russian, written inline as string literals (they are `LocalizedStringKey`).
  No String Catalog file exists yet.

## 7. Project structure

```
Bookshelf/
  App/          BookshelfApp — ModelContainer + root dependency wiring
  Models/       SwiftData @Model (Book, ReadingStatus — enums stored as raw strings)
  Services/     BookRepository protocol + SwiftDataBookRepository
  ViewModels/   @Observable @MainActor, depend only on BookRepository
  Views/        Screens and presentational components (+ #Preview)
  Assets.xcassets
BookshelfTests/ Swift Testing: ViewModel tests with InMemoryBookRepository, component logic
```

Organized by layer, not by feature. A new Figma screen usually means:
`Views/<Name>View.swift` + `ViewModels/<Name>ViewModel.swift` (created by the parent ViewModel,
e.g. `makeAddBookViewModel()`), plus tests for its logic.

## Figma → code checklist

1. `get_design_context` / `get_screenshot` for the node; read the result as a reference.
2. Map colors, text styles, icons and spacing using sections 1, 5 and 6 above.
3. Reuse existing views (`BookCoverView`, native `List`/`Form`/`ContentUnavailableView`).
4. Keep MVVM: data and validation in the ViewModel, the view only renders.
5. Add `#Preview` with key states; check light/dark and large text.
6. Build and run tests (commands in CLAUDE.md).
