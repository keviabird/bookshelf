# Design system rules (Figma → SwiftUI)

Rules for turning Figma designs (via the Figma MCP server) into code for «Книжная полка».
Figma MCP output is usually React + Tailwind: treat it as a **visual reference only** and
rewrite it in SwiftUI following the rules below. Never add web code, CSS or third-party UI libraries.

## 1. Tokens

**All design tokens live in `Bookshelf/Design/Theme.swift`** (`Theme.Colors`, `Theme.Fonts`,
`Theme.Metrics`). Views use `Theme.*` only — no hex values, `Color(...)` literals or ad-hoc fonts in views.
New colors and fonts are added there and nowhere else.

Colors mirror the Figma variable collection **Bookshelf** one-to-one:
`color/<name>` → Color Set `Shelf<Name>` → `Theme.Colors.<name>`. A new Figma variable gets a new
Color Set with that name (keep the `Shelf` prefix: plain `Accent` clashes with the symbol generated
for `AccentColor`). Figma has no dark values — dark variants are ours.

| Figma variable | `Theme.Colors` | Color Set | Light / Dark | Used for |
|---|---|---|---|---|
| `color/background-dark` | `backgroundDark` | `ShelfBackgroundDark` | #121921 / #000000 | header, detail background, cover placeholder |
| `color/surface` | `surface` | `ShelfSurface` | #FFFFFF / #1C1C1E | rounded sheets, text on selected chip/primary button |
| `color/text-primary` | `textPrimary` | `ShelfTextPrimary` | #121921 / #F2F2F7 | text, selected chip, primary button, list progress |
| `color/text-secondary` | `textSecondary` | `ShelfTextSecondary` | #6B7079 / #9A9FA8 | author on detail, captions, description |
| `color/text-on-dark` | `textOnDark` | `ShelfTextOnDark` | #FFFFFF / #FFFFFF | titles/icons on dark header, rank badge |
| `color/accent` | `accent` | `ShelfAccent` | #A28D4F / #C2AD6F | big numbers, header buttons, detail progress |
| `color/track` | `track` | `ShelfTrack` | #D9D9D9 / #3A3A3C | unselected chip, progress track |

In Figma the selected chip and primary button use `background-dark`; in code they use
`textPrimary`, which is the same #121921 in light mode but stays visible on the dark sheet.

`Theme.Fonts.*` — system fonts on Dynamic Type styles (mapping below).
`Theme.Metrics.*` — literals in pt: list sheet radius 48, cover 88×133, rank badge 44,
progress 5; detail cover 140×210 (radius 6), detail sheet radius 40, progress 4, primary button 52.

Fonts from the Figma file (Google Fonts) are replaced with system equivalents, so text follows
Dynamic Type: Montserrat → SF Pro (`.headline`, `.subheadline`, `.caption`…),
Alice → New York (`design: .serif`), Abel → condensed SF (`.width(.condensed)`) with tracking.

Errors still use system `.red`, banners `.bar`. `AccentColor` is empty (system blue) and only
affects system controls in forms.

Build settings: `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME = AccentColor`,
`ASSETCATALOG_COMPILER_GENERATE_SWIFT_ASSET_SYMBOL_EXTENSIONS = YES` (colors/images added to
the catalog get type-safe Swift symbols generated by Xcode).

**Mapping Figma values:**
- Figma color variables → a named Color Set in `Assets.xcassets` with **Any + Dark** appearances.
  Use it via the generated symbol or `Color("Name")`. Don't hardcode hex/RGB in views.
- If a Figma color matches a system color (label, secondary label, system background, red…),
  use the system semantic color instead of adding a new asset.
- Figma color variables → see the table above; check `get_variable_defs` for the node first.
- Figma text styles → nearest Dynamic Type style (`.largeTitle … .caption2`) + `.weight(...)`.
  Fixed `.system(size:)` only for tiny decorative text (e.g. `BookCoverView` placeholder),
  never for body copy — the app must support Dynamic Type.
- Figma spacing/radius → literal values in pt map 1:1. Sizes that define the look (cover, badge,
  radii) go to `Theme.Metrics`; one-off paddings can stay inline.
- Figma mockups without auto layout: never copy absolute coordinates, `.offset` or `.position`.
  Build with stacks/`List`; overlaps via negative stack spacing (see `BookRowView`).

## 2. Components

- Location: `Bookshelf/Views/`, one `struct …: View` per file, file named after the type.
- Two kinds of views:
  - **Screens** (`BookListView`, `AddBookView`) own a ViewModel via `@State`, injected in `init`.
    They never touch SwiftData or `@Query` (MVVM rule from CLAUDE.md).
  - **Presentational components** take plain values (`String`, `URL?`, enums, closures),
    not ViewModels or `ModelContext`. New Figma components go here. Existing ones:
    - list: `ShelfSummaryView`, `StatusFilterBar`, `RankBadge`,
      `ReadingProgressBar`, `BookRowView` (optional `rank`, `footer` slot; on the shelf — progress,
      in search — year + `AddToShelfButton`);
    - search: `BookSearchView` (`.searchable`), `AddToShelfButton`;
    - detail: `StatusPicker`, `ReadingProgressSection`, `StatView`, `AboutSection`, `UpdateProgressView`;
    - shared: `ShelfNavigationTitle` + `.shelfNavigationBar(title:)` (dark nav bar),
      `.shelfSheetBackground()` (dark top + rounded sheet), `StatusChip` (Figma «Status Chip»; optional `count` — with it in the list filter,
      without it in the detail), `ShelfProgressViewStyle(fill:height:)`, `PrimaryButtonStyle`
      (`.buttonStyle(.primary)`), `BookCoverView(size:cornerRadius:)`.
- Any non-trivial layout logic in a component is a `static func` so it can be unit-tested
  (see `BookCoverView.placeholderFontSize(for:)` + `BookshelfTests/BookCoverViewTests.swift`).
- Documentation = `#Preview` at the bottom of each file. Show the important states
  (empty, long text, error). Previews needing data build an in-memory `ModelContainer`.
- Prefer native containers over custom chrome: `NavigationStack`, `List`, `Form`/`Section`,
  `ContentUnavailableView` (empty/error states), `.toolbar`, `.sheet`.
  Don't use `ContentUnavailableView.search`: its text follows the app localization, and without
  a Russian one it shows «No Results for…». Build the empty search state with Russian text.

```swift
// Presentational component pattern (Bookshelf/Views/BookCoverView.swift)
struct BookCoverView: View {
    let title: String
    let coverURL: URL?

    var body: some View { … }

    static func placeholderFontSize(for title: String) -> CGFloat { … }
}

#Preview {
    HStack { BookCoverView(title: "Я", coverURL: nil) }
}
```

## 3. Frameworks & build

- SwiftUI only (no UIKit), SwiftData for storage, iOS 17.0 deployment target, Xcode 26.
  APIs newer than iOS 17 (e.g. Liquid Glass `.glassEffect`) need `if #available`.
- Swift 5 mode with `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor`.
- Build system: Xcode project with file-system-synchronized groups — new files under
  `Bookshelf/` are picked up automatically; don't edit `project.pbxproj`.
- No SPM packages. Don't add design/UI dependencies without approval.

## 4. Assets

- All bundled assets live in `Bookshelf/Assets.xcassets` (`AppIcon`, `AccentColor`, `Shelf*` colors).
- Figma images/illustrations → export as **PDF or SVG** (vector, "Preserve Vector Data") or PNG
  @2x/@3x, add as an Image Set, reference via generated symbol / `Image("name")`.
  Do not use the localhost asset URLs from Figma MCP output in code.
- App icon: single 1024×1024 with Any / Dark / Tinted variants (`AppIcon.appiconset`).
- Remote images (book covers) come from `Book.coverURL` and load with `AsyncImage`; always
  provide placeholder + failure states (see `BookCoverView`). No CDN or image cache layer.

## 5. Icons

- Use **SF Symbols** only: `Label("…", systemImage: "books.vertical")`, `Image(systemName:)`.
- Used today: `plus`, `magnifyingglass` (search; left in the list bar so the title stays centered),
  `checkmark` (book already on the shelf), `wifi.exclamationmark` (search error), `books.vertical`, `exclamationmark.triangle`, `line.3.horizontal.decrease.circle`,
  `bookmark` / `bookmark.fill` (favorite on the detail screen).
  The bell from the list header in Figma is replaced by the gold `plus` (add book).
- Figma icon → find the matching SF Symbol (SF Symbols app). Only if none fits, export it as an
  SVG **Symbol Image** into the asset catalog, named in kebab/dot style like SF Symbols
  (`book.cover.placeholder`).
- Icon-only buttons still use `Label` so VoiceOver gets text; decorative images get
  `.accessibilityHidden(true)`.

## 6. Styling

- No CSS concept: styling is SwiftUI modifiers applied inline in the view.
- Global style: `Theme` tokens + system light/dark appearance. Custom styles exist where a look
  repeats (`ShelfProgressViewStyle`); add new `ButtonStyle`/`ViewModifier`s in `Bookshelf/Views/`
  instead of repeating modifier chains.
- Colors for states: errors `.red`, text `textPrimary` / `textSecondary`, accents `accent`.
- Every screen in the main `NavigationStack` uses the system bar via `.shelfNavigationBar(title:)`:
  transparent background over `backgroundDark`, `toolbarColorScheme(.dark)`, caps title in `.principal`.
  Don't hide the bar on one screen and show it on the next: on push iOS 26 then grows the back
  button as a glass bubble over the old screen (a white flash). Bar buttons are colored with
  `.tint(Theme.Colors.accent)`. Forms/sheets keep the standard navigation bar.
- Every new screen must work in **light and dark** mode and with large Dynamic Type sizes.
- Responsive layout: app runs on iPhone and iPad (`TARGETED_DEVICE_FAMILY = 1,2`), portrait and
  landscape. Use flexible stacks/`List`/`Form`, `Spacer`, `frame(maxWidth:)`; avoid fixed screen
  widths. Fixed sizes are fine for small elements (cover thumbnail 48×72).
- UI strings are Russian, written inline as string literals (they are `LocalizedStringKey`).
  No String Catalog file exists yet.

## 7. Project structure

```
Bookshelf/
  App/          BookshelfApp — ModelContainer + root dependency wiring;
                SampleData (DEBUG): preview data, launch arguments for screenshots:
                `-seedSampleBooks`, `-openBookIndex N`, `-openSearch "query"`
  Design/       Theme — colors, fonts, metrics
  Models/       SwiftData @Model (Book, ReadingStatus — enums stored as raw strings)
  Services/     BookRepository protocol + SwiftDataBookRepository;
                Search/ — BookSearchService, OpenLibrarySearchService, DTOs, OpenLibraryMapper
  ViewModels/   @Observable @MainActor, depend only on BookRepository
  Views/        Screens and presentational components (+ #Preview)
  Assets.xcassets
BookshelfTests/ Swift Testing: ViewModel tests with InMemoryBookRepository, component logic
```

Organized by layer, not by feature. A new Figma screen usually means:
`Views/<Name>View.swift` + `ViewModels/<Name>ViewModel.swift` (created by the parent ViewModel,
e.g. `makeAddBookViewModel()`), plus tests for its logic.

## Figma → code checklist

1. `get_design_context` / `get_screenshot` for the node; read the result as a reference.
2. Map colors, text styles, icons and spacing using sections 1, 5 and 6 above.
3. Reuse existing views (`BookCoverView`, native `List`/`Form`/`ContentUnavailableView`).
4. Keep MVVM: data and validation in the ViewModel, the view only renders.
5. Add `#Preview` with key states; check light/dark and large text.
6. Build and run tests (commands in CLAUDE.md).
